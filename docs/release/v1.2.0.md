# id-forge v1.2.0

Fixes from an independent review. Upgrade recommended for programs
that fork worker processes after minting IDs.

## What changed

- **Fork safety.** A child created with `fork()` no longer repeats
  the parent's random IDs (UUID v4 and v7, ULID, NanoID). The
  per-thread random buffer and the ULID state are discarded in the
  child before its next ID. A restored VM or container snapshot
  cannot be detected; the docs now say so.
- **Fallible generators.** `Uuid::try_v4`, `Uuid::try_v7`,
  `Ulid::try_new`, `nanoid::try_generate`, `nanoid::try_with_length`
  and `nanoid::try_with_alphabet` return an error instead of
  panicking when the OS random source fails. The panicking forms are
  unchanged and now document their panics.
- **Snowflake before the epoch.** `try_next_id` returns an error when
  the wall clock reads earlier than the epoch, and no wait lasts
  longer than `MAX_CLOCK_WAIT` (50 ms).
- **ULID ordering.** The guarantee is per thread, as it has always
  been; the docs said per process. ULIDs now also stay ordered when
  the wall clock steps back.
- **NanoID alphabets.** `try_with_alphabet` rejects non-ASCII bytes.
- **Faster `Uuid` formatting** through a lookup table.
- **Docs** on using IDs as secrets: compare in constant time or store
  a hash, and keep them out of logs.

## Compatibility

- Additive only; no public item removed or changed. MSRV stays at
  Rust 1.75.

## Upgrade

```toml
[dependencies]
id-forge = "1.2"
```
