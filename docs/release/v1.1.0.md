# id-forge v1.1.0

**Security release. Upgrade recommended wherever IDs act as tokens or
unguessable references.**

Random IDs now come from the OS random source. `Uuid::v4`, `Uuid::v7`,
`Ulid::new` and every `nanoid` generator draw their random bits from
the operating system, read in blocks into a per-thread buffer so most
IDs cost no system call. No public signature changed.

## What changed

- **OS random source.** Random bits come from the operating system
  through the first-party `mod-rand` crate (`tier3`: `getrandom` on
  Linux, `getentropy` on macOS, `BCryptGenRandom` on Windows).
- **No weaker fallback.** If the OS random source cannot be read,
  generation panics. On supported platforms the source blocks rather
  than fails; see the panic table in `docs/API.md`.
- **Dependencies.** `mod-rand 1.0` is the one runtime dependency,
  enabled by the `uuid`, `ulid` and `nanoid` features. It is
  first-party and depends on nothing outside `std`, so `id-forge` still
  has no third-party runtime dependencies.

## Performance

Single thread, release profile, `examples/bench.rs` on Windows x86-64:

| Generator          | 1.0.0     | 1.1.0     |
|--------------------|-----------|-----------|
| `Uuid::v4`         | 20.5 ns   | 19.8 ns   |
| `Ulid::new`        | 32.4 ns   | 46.7 ns   |
| `nanoid::generate` | 84.2 ns   | 123.5 ns  |

Numbers are informational and vary from run to run.

## Compatibility

- No public signature changes. ID formats, the v7 and ULID ordering
  guarantees, and NanoID alphabet handling are unchanged.
- MSRV stays at Rust 1.75.

## Upgrade

```toml
[dependencies]

```
